# Security Policy

We take the security of this project seriously. If you believe you have found a
security vulnerability, please follow the reporting instructions below.

## Supported Versions

Only the latest release and the most recent minor versions receive security
updates. Older versions are not supported and may contain unpatched
vulnerabilities.

| Version | Supported          |
| ------- | ------------------ |
| 1.x     | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

**Please do not open a public issue for security vulnerabilities.**

To report a vulnerability, contact the maintainers privately via email at
`security@example.com`. Please include as much of the following information as
possible to help us triage and fix the issue quickly:

- The affected version(s) and environment.
- A clear, step-by-step description of how to reproduce the issue.
- The impact of the vulnerability (e.g. data exposure, denial of service).
- Any proof-of-concept or exploit code (sanitized if necessary).

### What to expect

- **Acknowledgement:** We will acknowledge receipt of your report within **48 hours**.
- **Status updates:** We will provide regular updates on the investigation and fix.
- **Disclosure:** We will coordinate disclosure with you and give credit where appropriate.

We ask that you give us a reasonable amount of time to fix the issue before
publicly disclosing it. We aim to respond to all reports within 90 days.
